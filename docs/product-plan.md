# What Grade 프로젝트 방향

- 작성일: 2026-10-02
- 상태: 초기 개발 기준. 응답 데이터와 사용 경험에 따라 조정한다.

## 목적

짧은 퀴즈를 풀고 자신의 학습 수준을 확인한 뒤 결과를 공유하고 다시 도전하는 웹앱을 만든다. 초기에는 문제를 푸는 흐름과 결과 공유의 재미를 검증한다.

실제 재학 학년을 맞히는 것으로 단정하지 않고, 평가한 개념에 대한 학습 수준을 학년 범위로 표현한다. 이후 전체 초등 수학과 상식 퀴즈로 확장한다.

## 첫 버전의 범위

- 대한민국 초등학교 1~6학년의 수와 연산을 중심으로 출제한다.
- 계산과 수 개념을 평가하며, 도형·측정·자료 해석은 후속 단계에 추가한다.
- 로그인 없이 총 10문제 고정으로 진행한다.
- 답변에 따라 출제 수준을 조절한다.
- 결과 화면에서 학습 수준 범위와 잘 푼 개념, 어려웠던 개념을 보여준다.
- 결과 요약 복사와 지원되는 환경의 모바일 공유 기능을 제공한다.
- 결과 화면에서 다시 도전할 수 있다.

첫 버전에는 계정, 서버 기록 저장, 경쟁 랭킹을 포함하지 않는다. 영역별 평가를 충분히 하지 않은 상태에서 전체 수학 수준을 진단했다고 표현하지 않는다.

## 사용자 흐름

모바일과 아이패드를 우선 대상으로 설계한다. 휴대폰에서는 한 손으로 답을 고르고 다음으로 이동할 수 있게 하며, 아이패드는 가로·세로 및 분할 화면에 맞춰 배치한다. 버튼은 최소 48px 터치 영역을 확보하고, 작은 화면에서도 글자와 답안이 잘리지 않게 한다. 휴대폰의 다음 버튼은 하단에 유지하며 홈 표시줄 안전 영역을 반영한다.

1. 시작 화면에서 평가 범위와 총 10문제라는 안내를 확인한다.
2. 중간 수준의 문제부터 시작한다. 초기 기준은 3학년 수준이며 실제 응답을 보고 조정한다.
3. 총 10문제를 풀며 답변에 따라 출제 수준이 달라진다. 진행 상황은 `현재 문항 / 10`으로 표시한다.
4. 학습 수준 범위와 개념별 결과를 확인한다.
5. 결과를 공유하거나 다시 도전한다.

시험보다 가벼운 도전처럼 느껴지도록 하고, 오답에도 부담을 주지 않는 문구를 사용한다.

## 기술 및 배포

| 항목 | 초기 선택 |
|---|---|
| 화면 | React + TypeScript + Vite |
| 코드 및 데이터 관리 | GitHub 저장소 |
| 배포 | Cloudflare Workers의 정적 파일 호스팅 |
| 문제 관리 | 저장소의 JSON 파일 |
| 출제 및 채점 | 브라우저에서 실행 |
| 서버 및 데이터베이스 | 첫 버전에는 도입하지 않음 |

화면, 문제 데이터, 출제·채점 로직을 분리한다. 출제·채점 로직은 화면 컴포넌트에 종속되지 않게 구성하여 후속 서버 채점으로 이전하기 쉽게 만든다.

브라우저에 문제와 정답이 전달되므로 정답을 확인할 수 있는 구조다. 경쟁 랭킹을 도입할 때는 서버가 출제 및 채점의 기준을 관리하도록 변경한다.

## 문제은행 원칙

교육과정의 공식 학년군과 앱의 출제 학년을 함께 관리한다. 학년과 난이도를 구분하고, 같은 학년의 기초 문제와 응용 문제를 별도로 분류한다.

문제에는 다음 정보를 포함한다.

- 고유 ID, 과목, 교육과정
- 학년군, 출제 학년
- 영역, 세부 개념, 선수 개념
- 난이도, 평가하는 능력
- 질문, 선택지 또는 답변 형식, 정답, 해설

수학 문제는 학년별 JSON 파일로 관리한다. 상식 문제는 추후 별도 과목으로 추가하며 수학 학습 수준과 다른 결과 기준을 사용한다.

교육과정 분류와 검증 상태는 [초등 수학 영역 문서](curriculum/elementary-math.md)를 따른다. 문제 수와 영역 비중은 학년별 핵심 개념에 맞춰 정하며, 영역마다 같은 비중을 강제하지 않는다.

## 출제 및 수준 추정 원칙

- 한 문제의 정오답만으로 학습 수준을 확정하지 않는다.
- 비슷한 수준의 다른 개념 문제를 통해 정답과 오답의 경향을 확인한다.
- 첫 버전은 설명 가능한 단순한 규칙으로 출제 수준을 조절한다.
- 문제 난이도와 수준 추정 규칙은 실제 응답 데이터를 통해 검증하고 조정한다.
- 퀴즈는 10문제 응답 후 종료한다. 세부 점수 산식과 문제 선택 규칙은 구현 전 별도 문서로 확정한다.

## 결과 표현

결과는 “초등 3~4학년 수와 연산 수준”처럼 범위와 평가 대상을 함께 표시한다. 잘 푼 개념과 어려웠던 개념을 간단히 설명하고, 응답 근거가 부족하면 판단이 제한적임을 표현한다.

문제은행과 추정 규칙이 검증되기 전에는 정밀한 진단이나 실제 재학 학년 판별로 표현하지 않는다.

## 개발 순서

1. 수와 연산 중심의 학년별 개념을 교과서·성취기준과 대조한다.
2. 문제 데이터 형식과 문제 작성 규칙을 정한다.
3. 작은 문제 세트와 출제·채점 규칙을 만든다.
4. 시작 → 퀴즈 → 결과 → 공유·재도전 흐름을 구현한다.
5. Cloudflare에 배포하여 사용자 경험을 확인한다.
6. 실제 사용 경험에 따라 문제와 결과 표현을 개선한다.

## 이후 확장

| 단계 | 확장 내용 | 도입 조건 |
|---|---|---|
| 수학 범위 확대 | 도형·측정·변화와 관계·자료와 가능성 | 해당 개념의 문제와 평가 근거를 확보했을 때 |
| 재미형 퀴즈 | 상식 과목과 별도 결과 표현 | 수학 퀴즈의 기본 흐름을 검증한 뒤 |
| 기록 저장 | API와 데이터베이스, 필요시 계정 | 반복 이용 기록을 저장할 필요가 확인될 때 |
| 경쟁 랭킹 | 서버 출제·채점과 기록 검증 | 순위의 신뢰성이 필요한 기능을 도입할 때 |

## 아직 확정하지 않은 사항

- 초기 문제은행의 문제 수와 난이도별 배분
- 구체적인 적응형 출제 및 수준 추정 산식
- 문항별 해설을 보여주는 시점
- 상세 화면 디자인과 공유 결과 형식
- 사용자 반응을 확인할 방법 및 기록 수집 여부
- 도메인과 실제 배포 계정 설정
